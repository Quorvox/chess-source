# QuorChess

Шахматный сайт с рейтингом, ботами, турнирами и друзьями. Работает на собственном небольшом сервере: один процесс Node.js, SQLite, без сборки фронтенда.
Живой пример: https://chess.quorvox.ru

*English: a self-hosted chess site (rated games, bots 1–10, tournaments, friends, Telegram bot, hidden 2FA admin). One Node.js process + SQLite, vanilla ES-module frontend, AGPL-3.0-or-later. Setup notes below are in Russian.*

## Что умеет

- **Рейтинговые партии.** Судья сервер: ходы проверяет chess.js, часы считает сервер, выход из партии наказывается. Подбор соперника, при отсутствии людей подставляется бот под рейтинг.
- **Боты 1–10** (Stockfish): в браузере для тренировки, на сервере для рейтинга. Настройки каждого бота: шанс принять и предложить ничью, плашка «бот», онлайн 24/7, история и фразы в чате.
- **Турниры:** арена по времени, швейцарская система и игра на выбывание. Жеребьёвка при старте, автоматические пары, уведомления на сайте и в Telegram, призы за места, правка сетки в админке.
- **Друзья:** заявки, онлайн, приглашение сыграть. **Комнаты** по коду (партию судит хост, сервер только пересылает). **Игра вдвоём на одном экране.**
- **Профили:** рейтинг и звания, трофеи, галочки (зелёная автоматически, синяя и золотая выдаёт админ), скины досок и фигур, наборы звуков, два стиля сайта (классика и минимал), RU и EN.
- **Telegram-бот:** вход по одноразовой ссылке, заявки на галочки, топ и турниры, уведомления.
- **Скрытая админка** на отдельном адресе: пароль + код из приложения (TOTP), блокировка после неудач, журнал действий, игроки и боты (массовые действия), партии, турниры, заявки, настройки, резервные копии базы.

## Стек

Node.js 22.13+ (встроенный `node:sqlite`), Express 5, `ws`, chess.js, chessground, Stockfish (WASM в браузере, процесс на сервере), nodemailer. Фронтенд на чистом JS (ES-модули), без сборщика.

## Запуск у себя

```bash
npm install            # заодно копирует доску и Stockfish в public/vendor
npm start              # http://localhost:3410
node scripts/smoke.js          # проверка сервера: игра, комнаты, админка, турниры, бот Telegram (на поддельном Telegram)
node scripts/bracket-test.js   # движок турнирной сетки
node scripts/check-i18n.js     # все ключи переводов на месте
LOAD_N=40 node scripts/loadtest.js   # нагрузка: N игроков одновременно играют с ботами
```

## Настройка (переменные окружения)

Файл `.env.example` показывает все переменные. Реальные значения хранятся только на сервере (`/etc/quorchess.env`), в git их нет.

| Переменная | Зачем |
|---|---|
| `PORT`, `DATA_DIR`, `PUBLIC_URL` | порт, папка с базой, публичный адрес сайта |
| `ADMIN_HOST` | отдельный скрытый адрес админки; без него админки нет |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | Telegram-бот и виджет входа |
| `SMTP_URL`, `MAIL_FROM` | письма подтверждения почты |
| `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` | вход через Discord |
| `BOT_BADGE`, `TG_POLL`, `TG_EMOJI` | необязательные переключатели |

### Админ

```bash
DATA_DIR=./data node scripts/admin-create.js <логин> <файл>
```

Скрипт создаёт админа и пишет пароль и ключ для приложения-аутентификатора **в файл** (права 600), а не в консоль. После входа файл нужно удалить.

## Как устроено

```
server/
  index.js        HTTP, API, WebSocket, вход, безопасность (CSP, защита от CSRF, лимиты)
  games.js        рейтинговые партии: ходы, часы, ничья, чат, рейтинг Эло
  mm.js           подбор соперника
  engine.js       один общий процесс Stockfish для ботов, гасится после простоя
  tournaments.js  арена и призы; bracket.js — швейцарка и олимпийка, жеребьёвка, пары
  admin.js        API админки; adminsite.js — скрытый сайт, вход, TOTP (totp.js)
  friends.js      друзья и приглашения; tgbot.js — Telegram-бот (long polling)
  backup.js       ежедневная копия базы (VACUUM INTO), db.js — схема и миграции
public/           сайт: js/views/* (страницы), js/lang/* (RU и EN), skins, звуки, фигуры
admin/            интерфейс админки (отдельная страница на скрытом адресе)
deploy/           systemd-юнит и примеры nginx
scripts/          проверки, нагрузочный тест, копии базы на свой компьютер
```

Принципы: сервер никому не верит (все ходы и часы проверяются на нём), админка не существует на публичном адресе, ключи только в окружении, база одна и маленькая.

## Выкладка на VPS (пример)

1. DNS: запись `A` на IP сервера.
2. Папку проекта в `/opt/quorchess`, `npm ci --omit=dev`, отдельный пользователь без shell.
3. `deploy/quorchess.service` в `/etc/systemd/system/` (ограничения памяти и прав уже внутри), `systemctl enable --now quorchess`.
4. nginx: `deploy/chess.quorvox.ru.nginx` для сайта, `deploy/admin-host.nginx.example` для скрытой админки, сертификаты через certbot.
5. Копии базы: сервер сам делает их раз в сутки в `data/backups`; на свой компьютер забирает `scripts/backup-pull.ps1` по расписанию (нужен SSH-ключ).

Копии делаются через `VACUUM INTO`: простое копирование файла базы в режиме WAL даёт пустую копию.
